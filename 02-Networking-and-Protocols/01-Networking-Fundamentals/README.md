# 01 — Networking Fundamentals

Build a practical foundation in computer networking for Linux, DevOps, and DevSecOps. This module explains how devices address one another, how packets move across networks, how common protocols work, and how to troubleshoot connectivity safely.

## Learning objectives

By completing this module, you should be able to:

- Explain the OSI and TCP/IP models and relate protocols to their layers.
- Distinguish MAC addresses, IPv4/IPv6 addresses, ports, and protocols.
- Understand private/public IP addresses, CIDR notation, subnet masks, gateways, and routing.
- Describe Ethernet, ARP, ICMP, TCP, UDP, DNS, DHCP, HTTP, HTTPS, and TLS at a beginner level.
- Use common Linux networking tools to inspect configuration and troubleshoot connections.
- Interpret basic packet captures and identify security-relevant network signals.
- Explain the purpose of firewalls, NAT, segmentation, VPNs, and least-privilege network access.

## Prerequisites

- Basic command-line skills.
- A Linux VM, WSL environment, or Linux host is useful but not mandatory.
- For packet inspection, Wireshark or `tcpdump` is optional.
- Use only systems and networks you own or have explicit permission to test.

## Topics

1. Networking concepts: hosts, links, packets, frames, bandwidth, latency, and throughput.
2. OSI and TCP/IP models.
3. Ethernet, MAC addresses, switches, ARP, and broadcast domains.
4. IPv4, IPv6, private/public addressing, loopback, and link-local addresses.
5. Subnet masks, CIDR, network/broadcast addresses, and usable host ranges.
6. Default gateways, routing tables, and route selection.
7. TCP versus UDP, ports, sockets, and common service ports.
8. DNS resolution and common DNS record types.
9. DHCP and automatic network configuration.
10. HTTP/HTTPS, TLS, certificates, and secure transport.
11. NAT, firewalls, network segmentation, VPNs, and basic zero-trust ideas.
12. Network troubleshooting and packet analysis.

## Common protocols and ports

| Protocol/service | Typical port | Purpose |
|---|---:|---|
| SSH | TCP 22 | Secure remote shell |
| DNS | UDP/TCP 53 | Name resolution and related DNS operations |
| DHCPv4 | UDP 67/68 | Dynamic IPv4 configuration |
| HTTP | TCP 80 | Web traffic without TLS |
| HTTPS | TCP 443 | HTTP protected by TLS |
| NTP | UDP 123 | Time synchronization |
| SMTP submission | TCP 587 | Email submission |
| IMAP over TLS | TCP 993 | Secure mailbox access |
| DHCPv6 | UDP 546/547 | Dynamic IPv6 configuration |

Ports are conventions, not proof of what is running. Services can use alternate ports, and UDP/TCP behavior differs.

## Lab setup

Suggested tools:

```bash
ip address
ip route
ip neigh
ss -tulpen
getent hosts example.com
curl -I https://example.com
```

Depending on your distribution, you may also use:

```bash
ping -c 4 127.0.0.1
tracepath example.com
dig example.com
sudo tcpdump -ni any 'port 53'
```

Install missing tools only from your distribution's trusted repositories. Some commands or flags vary by Linux distribution.

## Suggested learning path

1. Read the concepts and draw the OSI/TCP-IP models.
2. Identify your own IP address, interface, default route, and neighbor table.
3. Practice IPv4 subnet calculations.
4. Resolve a domain name and inspect HTTP response headers.
5. Compare TCP and UDP with examples.
6. Capture traffic generated by your own test requests.
7. Complete `practical.md` and compare your work with `solutions.md`.

## Safety and privacy

- Only capture traffic on networks and devices you are authorized to inspect.
- Packet captures can contain personal data, session metadata, or other sensitive information. Store them securely and delete them when no longer needed.
- Do not scan, intercept, or attempt to access third-party systems without explicit authorization.
- Avoid exposing public IP addresses, internal topology, DNS names, or packet captures in public repositories.
