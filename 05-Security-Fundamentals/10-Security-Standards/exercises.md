# Security Standards — Exercises

Use the concepts in `README.md` and `examples.md`. You may use a fictional organization for all exercises.

## Exercise 1: Distinguish the terms

Explain the difference between:
1. A standard
2. A framework
3. A control catalog
4. A regulation or contractual requirement
5. Certification
6. An attestation report

Give one example of each.

## Exercise 2: Match the use case

Match each use case to one or more suitable references and explain why:
- A. Organize a broad cybersecurity risk-management program.
- B. Prioritize practical baseline safeguards.
- C. Establish a formal information security management system.
- D. Determine payment-card security obligations.
- E. Define verifiable web application security requirements.

Use NIST CSF, CIS Controls, ISO/IEC 27001, PCI DSS, and OWASP ASVS.

## Exercise 3: Scope definition

A fictional SaaS company has a production cloud account, CI/CD pipelines, a support team, employee laptops, a payment provider, and a marketing website.

Write a short assessment scope. Identify at least three dependencies or boundaries that must be clarified before the scope is finalized.

## Exercise 4: Map risk to controls

Risk: A developer's compromised account could change application code and deploy it to production.

List five safeguards. For each, specify:
- Desired outcome
- Responsible owner
- Evidence that could show the safeguard is operating

## Exercise 5: Review a claim

A company says, “We have a security policy, so we comply with ISO/IEC 27001 and NIST CSF.”

Explain why this claim is insufficient. List the additional steps or evidence needed to make a defensible statement about implementation or conformity.

## Exercise 6: Create a gap register

Create three gap-register rows for these scenarios:
- No documented privileged-access review
- Vulnerability scans run, but findings are not assigned to owners
- Backups exist, but no restore test has been recorded

Include objective, current state, gap, risk, owner, next action, due date, and evidence.

## Exercise 7: Evidence quality

For a control requiring peer review of code, rank these evidence items from weakest to strongest and explain your ranking:
- A policy that says code review is mandatory
- A screenshot of branch-protection settings
- A sample of pull requests showing required approvals
- A test demonstrating direct pushes are blocked on protected branches
- An interview statement that developers usually review code

There may be no single universal ordering; explain what each item does and does not prove.

## Exercise 8: Exception management

A control cannot be implemented before a product launch. Write a time-bound exception record with a risk owner, rationale, temporary safeguards, monitoring, expiry date, review cadence, and closure criteria.

## Exercise 9: DevSecOps mapping

For each stage below, propose one security practice and one evidence source:
- Source control
- Build and dependency management
- Infrastructure as Code
- Container image creation
- Deployment
- Production monitoring

## Exercise 10: Standards implementation plan

Prepare a 30-day starter plan for a small organization that wants to improve security using a selected framework. Include:
- Scope and stakeholders
- Initial risk assessment
- Control selection and ownership
- Gap review
- Prioritized actions
- Evidence collection
- Management review

## Exercise 11: Short reflection

In 150–250 words, explain why adopting a framework is not the same as being secure or certified.
