# Session Management Security Checklist

## Creation and rotation
- [ ] Session identifiers are generated by a maintained framework/library using cryptographically secure randomness.
- [ ] Identifiers are opaque and contain no sensitive data.
- [ ] Session IDs rotate after login.
- [ ] Session IDs rotate after privilege changes and other sensitive transitions as appropriate.
- [ ] Pre-authentication identifiers cannot be used as authenticated sessions.

## Cookies and transport
- [ ] HTTPS is enforced throughout authenticated flows.
- [ ] Session cookies use `Secure`.
- [ ] Session cookies use `HttpOnly` unless a documented design requires otherwise.
- [ ] `SameSite` is selected based on the application's actual flows and threat model.
- [ ] Cookie `Domain` and `Path` scope are no broader than necessary.
- [ ] `__Host-` prefix is considered where compatible.
- [ ] Session IDs are not carried in URLs.

## Expiration and revocation
- [ ] Idle timeout is documented and enforced server-side.
- [ ] Absolute timeout is documented and enforced server-side.
- [ ] Logout invalidates server-side session state.
- [ ] Revoked or expired sessions cannot be replayed.
- [ ] Password changes, account recovery, MFA changes, and suspected compromise have a documented revocation policy.
- [ ] Administrative session revocation is supported where appropriate.
- [ ] Distributed services consistently enforce revocation.

## Request protections and authorization
- [ ] CSRF defenses protect cookie-authenticated state-changing requests.
- [ ] State-changing operations do not use `GET`.
- [ ] Origin checks are considered where useful.
- [ ] Authorization is checked on every protected request.
- [ ] Object ownership and role checks are enforced server-side.
- [ ] Sensitive actions require recent authentication or step-up verification where appropriate.

## Monitoring and leakage
- [ ] Raw session IDs, cookies, access tokens, and refresh tokens are excluded from logs.
- [ ] Proxy, analytics, crash-reporting, and application logs are reviewed for leakage.
- [ ] Suspicious session behavior is monitored proportionately.
- [ ] Users can review or revoke active sessions where feasible.
- [ ] Security events use sanitized identifiers and have appropriate access controls.
- [ ] Regression tests cover fixation, replay, logout, expiry, and CSRF behavior.
